# Промт для Claude Code: симулятор Девичьей башни

Как пользоваться: не вставляй весь файл разом. Отдавай **по одной фазе**,
проверяй результат в браузере, потом следующую. Claude Code хорошо держит
одну фазу и разваливается на двенадцати.

Перед первой фазой положи в корень проекта `maiden-tower-reference.md`
(файл с обмерами) и папку `reference-photos/`.

---

## Системный контекст (вставить один раз, в начале сессии)

```
Мы строим веб-симулятор прогулки по Девичьей башне в Баку —
исторически достоверная реконструкция интерьера с видом от первого лица.

Стек: React 19 + TypeScript + Vite, three.js через @react-three/fiber,
@react-three/drei, @react-three/rapier для физики. Без Next.js.
Таргет: 60 fps на десктопе, 30+ на среднем Android. Позже — WebXR.

Принципы, которым следуй всю сессию:
1. Вся геометрия — процедурная, из одного конфига размеров.
   Никаких магических чисел в компонентах. Меняю число в конфиге —
   меняется модель.
2. Единицы — метры. Y вверх. Север = -Z, восток = +X.
3. Каждая фаза заканчивается работающим `npm run dev` без ошибок в консоли.
4. Не выдумывай размеры. Если чего-то нет в maiden-tower-reference.md —
   спроси у меня, не подставляй правдоподобное значение.
5. Комментируй в коде, какое число откуда взято (источник).
6. Пиши тесты только для математики (геометрия, солнечные азимуты),
   не для рендера.

Прочитай maiden-tower-reference.md перед началом.
```

## Фаза 1 — Каркас проекта и конфиг размеров

```
Создай проект: Vite + React + TypeScript, установи three,
@react-three/fiber, @react-three/drei, @react-three/rapier, leva.

Сделай src/config/tower.ts — единственный источник правды по геометрии.
Возьми числа из maiden-tower-reference.md: высота 29.5, внешний диаметр
основания 16.5, толщина стены 5.0 внизу → 3.7 вверху (среднее из 3.2–4.2),
8 ярусов, фундамент -15 м.

Структура конфига:
- TOWER: общие размеры
- FLOORS: массив из 8 объектов { index, floorY, ceilingY, oculusRadius,
  wallThicknessAtLevel, innerRadiusAtLevel } — innerRadius вычисляется,
  не хардкодится
- BUTTRESS: азимут 90° (восток), длина, ширина, форма в плане
- ENTRANCE: азимут 135° (юго-восток), ширина, высота, Y
- WELL: диаметр 0.7, глубина 21, начинается на 2-м ярусе
- SITE: широта 40.3661, долгота 49.8372

Экспортируй хелперы: innerRadiusAt(y), wallThicknessAt(y).
Помни: стена сужается ИЗНУТРИ, внешний цилиндр почти вертикальный —
внутренний радиус растёт с высотой.

Отрисуй пока просто wireframe-цилиндр по этим числам + сетку пола
+ OrbitControls. Хочу увидеть пропорции.
```

## Фаза 2 — Оболочка башни

```
Замени wireframe на настоящую геометрию оболочки.

Используй three-bvh-csg (или three-mesh-bvh + собственный extrude,
на твой выбор — обоснуй) чтобы получить:
- внешний цилиндр 16.5 м, высота 29.5
- вычесть внутренний конус (радиус растёт с высотой по innerRadiusAt)
- добавить контрфорс на азимут 90°: клювообразный выступ, скруглённый
  в плане, идёт от основания вверх, сливается с телом башни
- вырезать вход на азимут 135°

Меш должен быть манифолдным — я потом буду вешать на него коллайдер.
Проверь через BufferGeometryUtils, что нет вырожденных треугольников.

Дай мне leva-контролы, чтобы крутить контрфорс и вход по азимуту —
хочу подобрать визуально по фото из reference-photos/.
```

## Фаза 3 — Ярусы, купола, окулюсы

```
Добавь 8 перекрытий.

Каждое — пологий каменный купол (не плоская плита!) с центральным
круглым отверстием. Источник: "each floor has a shallow vaulted roof,
a stone cupola that has a central opening".

Купол делай как lathe geometry: профиль дуги малой стрелы подъёма,
опирается на внутреннюю окружность стены, в центре — окулюс.
Радиус окулюса пока сделай параметром в конфиге, начни с 1.2 м.

Пол каждого яруса — плоский, кольцевой, с тем же отверстием под окулюс.

Важно: окулюсы всех ярусов соосны — снизу должно быть видно небо
через все 8 отверстий. Проверь это камерой из центра пола 1-го яруса.
```

## Фаза 4 — Лестница

```
Винтовая лестница, проходящая В ТОЛЩЕ стены, примыкая к внутренней
окружности ("connected by a staircase which abuts the circular wall").

Генерируй процедурно: для каждого яруса — сегмент лестницы, поднимающийся
от floorY до следующего floorY, вписанный в стену. Ступени как отдельные
инстансы (InstancedMesh), высота подступенка ~0.18-0.22 м, ширина марша
~0.9 м, внутренний радиус марша = innerRadiusAt(y) + небольшой зазор.

Направление закрутки — по часовой при подъёме (проверь по фото
в reference-photos/interior/, если там видно; если не видно — спроси меня).

Вырежи проход в куполе там, где лестница выходит на следующий ярус.
Каждая ступень должна иметь коллайдер — я по ним буду ходить.
```

## Фаза 5 — Окна и ниши

```
Добавь оконные проёмы. Ключевая деталь: они узкие снаружи и
РАСШИРЯЮТСЯ ВНУТРЬ ("narrow windows or niches which flare inward").
То есть проём — усечённая пирамида, узкая грань наружу.

Сделай конфиг WINDOWS: массив { floorIndex, azimuth, heightAboveFloor,
outerWidth, outerHeight, innerWidth, innerHeight }.

Пока азимуты я не знаю точно — сгенерируй по одному окну на ярус
с азимутами, которые я потом поправлю через leva. Заведи под это
отдельный JSON, чтобы я мог редактировать без пересборки.

Отдельно: центральное окно, в которое по гипотезе Исламова попадает
луч на восходе в зимнее солнцестояние. Пометь его флагом
`solsticeAligned: true` — оно понадобится в фазе 8.
```

## Фаза 6 — Контроллер от первого лица

```
Первое лицо. @react-three/rapier: капсульный коллайдер (радиус 0.3,
высота 1.75), PointerLockControls, WASD + Shift для бега.

Требования:
- лестница проходима: настрой maxSlopeClimbAngle и autostep так,
  чтобы капсула шла по ступеням без застреваний
- нельзя проваливаться сквозь окулюсы — по краям отверстий
  нужны коллайдеры
- плавное падение в колодец, если туда шагнуть (это фича, не баг —
  добавь потом отдельный вид "внутри колодца")
- телепорт-хоткеи 1..8 — прыжок на нужный ярус, для дебага
- на мобильном: виртуальный джойстик слева, свайп для камеры

Высота глаз 1.65 м. Скорость ходьбы 1.4 м/с — это реальная скорость,
не делай 5 м/с как в шутерах, иначе масштаб башни не читается.
```

## Фаза 7 — Материалы

```
Материалы известняка.

Ключевая визуальная черта: чередующиеся ряды камня на гипсовом растворе
дают ЧЁРНО-БЕЛУЮ ПОЛОСАТОСТЬ по горизонтали. Плюс ромбовидная фактура
кладки, декоративная вверху, простая внизу.

Сделай процедурный шейдер:
- горизонтальные полосы по мировой Y с периодом ~0.35 м (высота ряда
  кладки), контраст настраиваемый
- ромбовидный normal map, генерируемый в коде, интенсивность растёт с высотой
- лёгкая вариация цвета по noise, чтобы не было пластика

Референс по цвету бери из reference-photos/exterior/ — вытащи среднюю
палитру и подставь. Не выдумывай "теплый песочный", смотри на реальные фото.

Внутри — темнее и более выветренная поверхность, шероховатость выше.
```

## Фаза 8 — Солнце и небо (тут проверяем гипотезу)

```
Это самая интересная часть. Ставим астрономически корректное солнце.

Установи suncalc. Позиция башни: 40.3661 N, 49.8372 E.

Сделай:
- SunSystem: по дате+времени считает азимут и высоту солнца, ставит
  directionalLight, обновляет Sky (drei) и тени
- UI-скраббер: дата (слайдер по году) + время суток. Пресеты-кнопки:
  зимнее солнцестояние, летнее солнцестояние, весеннее и осеннее
  равноденствие, Новруз
- визуализация луча: когда солнце попадает в проём, рисуй объёмный
  световой конус (godray) через проём внутрь башни
- индикатор "луч попал в окно X" — детекция raycast'ом от солнца
  через проём

Это должно дать возможность проверить утверждение Исламова:
на восходе 21 декабря луч заходит точно в центральное окно.
Если при реальных азимутах не сходится — так и покажи. Не подгоняй
геометрию под гипотезу.

Добавь режим отладки: горизонтальный компас-диск под башней
с отметками азимутов восхода в ключевые дни года.
```

## Фаза 9 — Колодец и водосбор

```
Добавь гидросистему — она хорошо документирована и почти нигде не показана.

- колодец Ø 0.7 м, глубина 21 м, вход на 2-м ярусе и с уровня земли
- керамическая труба Ø 30 см из ниш вниз в колодец
- полукруглые жёлобы на ярусах со 2-го по 7-й: керамические трубы
  Ø 20-25 см, стенка 2.2 см, сегменты по 40-45 см
- ниже уровня земли — четырёхугольные трубы 22 × 18 см, снаружи сквозь стену

Сделай отдельный слой визуализации "Водосбор": по кнопке стены
становятся полупрозрачными, трубы подсвечиваются, анимируется
поток воды сверху вниз в колодец.
```

## Фаза 10 — Слой гипотез

```
Ключевая фича: башня — спорный объект, и приложение должно это показывать,
а не выдавать одну версию за истину.

Сделай переключатель "Версия назначения" с вариантами:
1. Оборонительная цитадель (XII в.) — консенсус UNESCO
2. Зороастрийский храм огня (Ахундов) — 7 огней наверху,
   визуализируй огни на кровле
3. Дахма / башня молчания
4. Астрономическая башня (Ахмедов) — подсветить 30 нижних и 31 верхний
   выступ, привязать к дням месяца
5. Солнечный храм (Исламов) — включить визуализацию луча из фазы 8
6. Колонна для перегонки нефти (Ибрагимов)
7. Маяк (XVIII–XIX вв.) — задокументировано

Каждый режим: меняет освещение/декор/подсветку соответствующих элементов
+ панель с аргументами ЗА и ПРОТИВ и ссылкой на источник.
Данные держи в src/data/hypotheses.ts, тексты на трёх языках: az, ru, en.

Ни один режим не помечается как "правильный".
```

## Фаза 11 — Оптимизация

```
Профилируй и оптимизируй под 30 fps на среднем Android.

- InstancedMesh для ступеней, блоков кладки, труб
- запеки освещение в lightmap для статики, оставь динамическим
  только солнце
- LOD: дальние ярусы упрощаются
- frustum culling по ярусам: рендерим текущий ярус ± 1
- draco/meshopt сжатие для всего, что грузится как файл
- Suspense + прогресс загрузки

Покажи мне до/после: draw calls, треугольники, ms на кадр.
```

## Что держать в голове

Порядок фаз не случайный. Конфиг размеров первым — иначе к пятой фазе
у тебя будут магические числа в двенадцати файлах и любая правка обмеров
сломает всё. Солнце после окон — иначе нечего проверять. Оптимизация
последней — раньше нет смысла, профиль ещё не сформировался.

Если Claude Code начнёт выдумывать размеры вместо вопроса — останови
и напомни правило 4 из системного контекста. Это самый частый способ
получить красивую, но выдуманную башню.
